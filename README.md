# BoxMouse

本地运行的 macOS 鼠标手势自动化工具。把鼠标轨迹（可叠加修饰键）转换成快捷键、应用启动、窗口管理与媒体控制，并按全局或指定应用建立精细配置。

- 当前版本：**1.0.30**
- 作者：ccvi1223 · ccvi1223@qq.com
- 适用：macOS 15 及以上 · Apple 芯片（目标环境 macOS 26 / M5）

---

## 快速开始

```bash
./build-app.sh --install      # 构建并安装到 /Applications
```

首次启动会自动弹「辅助功能」授权引导。**没有这个权限，手势一条都不会触发**——事件监听（CGEventTap）必须有它。授权后状态会自动刷新，一般不需要重启。

试第一条手势：

1. 「手势」页 → 右上角「添加」→ 新建鼠标手势
2. 在轨迹框里按住鼠标画一笔
3. 选触发方式、动作、作用域 → 保存
4. 到任意应用里按住右键画同样的形状

画完没反应，先去「手势测试」里画一笔看相似度——比到系统里瞎试快得多。

## 识别算法

三步，全在 `Engine/PathRecognizer.swift`（1.0.12 重写，用户报"折线手势要画好几次才命中"）：

1. **重采样**：按弧长等距取 32 个点。抹掉"画得快/画得慢"的差异。
2. **归一化**：重心归零，**等比**缩放到最长轴 [-1,1]。
   - 🔴 为什么必须等比：旧版"按轴各自缩放 + 短轴死区"会**破坏角度**——16° 的斜线
     被短轴下限放大成 39°，折线的方向证据整个失真。DTW 与段角度都天然容忍臂长
     比例，按轴缩放不再必要。
   - 手抖不在这里处理：匹配层的 `flatByDirection` 按"整体走向"对称压轴。
3. **比对**（四路多尝试取最高，每路 = 0.62×DTW + 0.38×RDP 段角度）：
   - **DTW**：动态时间规整对齐，转角落在哪个采样序号不再敏感。
   - **RDP 段角度**：先 Ramer–Douglas–Peucker 简化掉手抖，剩下的每段取连续角度
     （不用 8 方位量化——量化在 22.5° 边界两侧会把差 7° 的方向判成不同字符），
     段数不同做 DP 对齐。
   - 四路尝试：原始 / 双方按整体走向压平短轴（直线类手抖）/ 双方裁掉首尾 8%
     （起笔小勾）/ 两者结合。多尝试只放宽"同一形状的不同画法"，不放宽不同形状。
   - `flatByDirection` 必须先验**直线度**（整条轨迹贴着首尾连线才压）：拱形/弧线
     的首尾向量也可能是水平的，不检查就把弧线压成直线（实验里直线 vs 弧线 0.985）。
   - 显示层另有 `displayStraighten`：只影响缩略图/录入框的渲染，不动识别数据。

阈值 0.78，实验校准（25 个手绘变体 × 6 类形状）：正例最差 0.784，负例最高 0.657，
自检把同一组数据固化在 `testZigzagRecognition`（闪电 / Z 形的臂长、圆滑、小勾、倾斜、
漂移变体必须一次命中，六类形状两两不误判）。同向但臂长不同的"闪电变体"算同一种
形状，不当负例——手画时根本区分不开。

## 界面约定

- **轨迹框固定 200 高**（宽 580）。更扁的时候（4:1）用户从上往下画"竖线"，手一漂就是 20% 的斜，会被识别成斜线。
- **所有控件左边缘必须跟上方 `SectionLabel` 齐平**。SwiftUI 的 `Picker` 默认 `alignment: .center`，
  `.segmented` 样式的固有宽度比 `frame` 窄，会被推到框中间——看着就是"选项比标题右移了一大截"，
  而 menu 样式的下拉本来就是左对齐，所以只有分段控件会露馅。每个 `Picker` 都写 `.frame(width:alignment:.leading)`。
- **修饰键是叠加条件，不是触发方式**。1.0.6 及以前把它做成了「按住 Fn 移动指针绘制」，
  这是错的：Fn + 移动在系统里是滚动、⌘ + 拖拽是选文件，都抢不过系统。现在缩成一行
  5 个可多选的方块（fn ⌘ ⌥ ⌃ ⇧），点了就是"按住这些键 + 画手势才生效"，不点就是裸手势。
  老配置里 `trigger` 写成 `command` 之类的，解码时迁移成「右键 + ⌘」。
- **应用组面板在组名下方常驻徽章区**（数量 + 可单独移除的胶囊 + 全部清空）。扫描未完成时显示"读取中…"，
  **不能**回落 bundle id：一串 `com.google.Chrome` 配问号文件夹，会被读成"选中的应用全没了"。
- **徽章区高度要按内容量出来，不能只写 `maxHeight`**。ScrollView 在垂直方向贪婪，
  给了 64 就吃满 64——只有一行徽章时底下白留 40 多点，看着像"中间空了一块"。
  用 `PreferenceKey` 量 FlowLayout 的真实高度回填 `frame(height:)`。

## 权限与安全

- 两项授权，各管一半：
  - **辅助功能**（Accessibility）——读鼠标事件、发合成按键、操作窗口。没有它鼠标手势一条都不触发。
  - **输入监控**（Input Monitoring）——触摸板手势专用。`MultitouchSupport` 读的是 `IOHIDEventSystemClient`，归这一项管，辅助功能替代不了。缺它时引擎会"启动成功"、设备也列得出来，但一个触点帧都收不到，界面上完全看不出是权限问题。
- **bundle id 是 `com.pcxx.boxmousemac`**。老的 `com.pcxx.boxmouse` 菜单栏登记已经烧了（见下面的铁律），换 id 之后系统会把它当成一个新应用，**辅助功能要重新授权一次**；旧授权记录在系统设置里会显示成一条已经失效的 BoxMouse，可以移除。
- 不做联网、不上传配置、不写系统级文件。
- 触摸板不触发时先看 `~/Library/Application Support/BoxMouse/trackpad.log`：第一行 `start ok` 会带上两项授权的实时状态；手指落下时写一行 `起手：修饰键 …`（这一行决定候选能不能匹配上）；手指抬起来写一行 `round → 轻点(3) 手指 3 修饰键 无`；每 60 帧写一次原始帧样本。只有 `start ok` 没有 `frame` = 没收到帧（权限）；有 `frame` 没 `round` = 收到了但没识别成手势（阈值）；有 `起手` 但候选不命中 = 修饰键对不上。
- **先开应用、后授权的情况要点一次「重启引擎」**。触控板设备是在应用启动那一刻起的，那会儿还没权限，设备就以「没权限」的状态跑着，之后授权也不会自己好。权限页的「重启引擎」按钮会把它停掉再起一次（退出时不会去停设备——那会崩）。
- 「权限」页底部的**触摸板自检**面板直接显示引擎收到的帧数：帧数一直 0 = 系统没把触点送进来；帧数在涨 = 数据正常，问题在识别。
- 配置位置：`~/Library/Application Support/BoxMouse/`（`gestures.json` 手势与作用域 / `settings.json` 设置）。这两个文件拆分是为了「改个滑块不用重写整份手势库」；**备份**走「通用 → 配置 → 备份配置」，一个文件把两个都装进去。
- 恢复配置是**整体替换**（回到备份那一刻），不是合并；覆盖前会自动把当前配置写成 `恢复前快照-<时间>.json` 放在同一个文件夹，最多留 3 份。
- 关掉窗口不退出（引擎要在后台继续监听），⌘Q 或菜单退出。
- 隐藏 Dock 图标后应用变成「菜单栏应用」（`NSApp.setActivationPolicy(.accessory)`）。此时窗口照常可点、快捷键照常有效，但 macOS 的规则是这类应用不接管菜单栏——菜单栏左上角仍显示上一个应用的名字，属于系统行为，不是故障。

## 三个系统开关（隐藏桌面图标 / 显示隐藏文件 / 锁定键盘）

放在**菜单栏浮窗**而不是设置页：这三项管的是"系统长什么样"，跟手势库没关系，属于"顺手按一下"的东西。

共同设计：**真相在系统里，不在我们的配置文件里**。三项都不持久化，每次显示浮窗前由 `MenuBarController` 现场重读（`SystemTogglesModel.refresh()`）——用户可能在别处改过（Finder 自己的显示选项、系统把事件 tap 掐掉），存一份副本只会让界面和事实打架。浮窗是常驻不重建的，所以也不能靠 `onAppear`。

| 开关 | 落点 | 为什么这么做 |
| --- | --- | --- |
| 隐藏桌面图标 | `com.apple.finder` 域的 `CreateDesktop` | 关掉只是 Finder 不往桌面铺图标，**文件一个都不动**，全在 `~/Desktop` 原地——所以敢做成一键往返。键不存在 = 从没动过 = 显示中 |
| 显示隐藏文件 | 同一个域的 `AppleShowAllFiles` | 🔴 这个键**不属于全局域**。写成 `NSGlobalDomain`（哪怕用 `defaults write -g` 这条"官方推荐"路子），defaults 命令读着是 true，Finder 自己却不认——它只查自己的域 |
| 锁定键盘 | HID 层的 `CGEventTap` | 命中 `keyDown` / `keyUp` / `flagsChanged` 就返回 `nil`，事件被吞掉，键盘等于断线。鼠标/触控板不在掩码里 |

三个细节：

- **写偏好用 `CFPreferencesSetAppValue` + `Synchronize`，不调 `defaults` 子进程**。子进程那套出过"写着成功、Finder 不认"的问题，而且多一层进程就多一次失败可能。改完 `killall Finder` 让 Finder 重读；这条命令要等到 Finder 退完才返回（约 0.5~1s），所以**放到后台线程跑**，否则浮窗的开关会卡一下。
- **键盘锁锁不死人**（三条保证）：① tap 挂在我们的进程上，进程一死（崩溃 / 被杀 / 退出）tap 自动拆除，键盘立刻恢复；② `applicationWillTerminate` 里主动 `unlock()` 双保险；③ 系统若因超时或用户输入临时禁用 tap，回调里重新 `tapEnable`。
- **没授权就不锁**。HID 级 tap 要「辅助功能」授权，未授权时 `CGEventTapCreate` 会失败或静默失效。开关拨到开但没授权时**不假装成功**：弹系统授权引导、开关回弹、行内副标题换成橙色的「需要授权：系统设置 → 隐私与安全性 → 辅助功能」。

**已知取舍**：键盘锁着的时候 Esc 也送不到应用，手势的键盘快捷键同样不触发——这是"到底锁没锁住"的必然结果。想解开只能用鼠标点浮窗里的开关，所以浮窗本身绝不能跟着被锁。

## 鼠标控制（滚轮 / 附加按键）

入口是顶部第二个标签「鼠标」，紧挨「手势」——这两块本来就是同一件事的两种触发方式，
用户找"鼠标还能干什么"的时候不该跨页翻。

**这一页和「手势引擎」总开关平级，互不隶属**。用户完全可能只想用平滑滚轮、一条手势都不想要，
所以它有自己的一级开关（`mouseControlEnabled`）；tap 该不该挂由
`BoxMouseSettings.needsEventTap = engineEnabled || mouseControlActive` 决定，
任何一项在生效就得挂着，否则功能会"静默失效"（面板一切正常，滚轮却没人接）。

平滑滚轮的算法参照了两个成熟实现，各取所长：

- **Mos（Caldis/Mos）** 取运动模型：**目标位移 + 逐帧逼近**。`buffer` 是目标（同向**累加**），
  `current` 是已经画出去的量，每帧 `step = (buffer - current) × factor`。同向连续输入累加进
  buffer，所以"越滚越快"是自然结果而不是额外写的加速逻辑；反向输入直接把 buffer 换成新值、
  current 归零——否则手指已经反过来了，屏幕还在往原方向飘一截。它的「速度增益」只在连续
  滚动时乘到输入上，我们照做。
- **Mac Mouse Fix（noah-nuebling/mac-mouse-fix）** 取两件事：① **亚像素**（它为此专门写了
  `VectorSubPixelator`）；② **收尾判定看"距离和速度都够小"**（`stopTolerance`），只看剩余
  距离会在尾巴上一直发空事件。它的 `HybridCurve`（先匀速、再切拖拽曲线）是给触控板式惯性
  用的，我们的输入是离散档位、没有 momentum 阶段，用不上；`DynamicSystemAnimator` 是给 UI
  动画的弹簧模型（源码注释自己也这么说）。

| 项 | 语义 | 关键实现 |
| --- | --- | --- |
| 平滑滚动 | 把鼠标滚轮的一格（约 3 行）摊成逐帧**亚像素**滚动，带缓动收尾 | `Engine/SmoothScroller.swift`：**CVDisplayLink 驱动**（60/120Hz 自适应）、按实测 dt 算每帧系数、通过 `FixedPtDelta` 送出小数 |
| 滚动距离 | 力度倍率 0.5–2.0× | 一档滚轮折算基准 40px（`baseLineHeight`），再乘倍率。想对齐 Mos 的「最短步长 48」，1.2–1.6× 就够 |
| 缓动时长 | 一格滚轮走到位的总时间，0.10–0.50 s | 内部换算成时间常数 τ = duration/3（3τ ≈ 95%），**按实测 dt 反推每帧系数**，换屏幕不变调 |
| 速度增益 | 连续滚动时的额外加速，1.0–3.0× | 只在上一次还没走完（余量 > 1px）时乘到输入上；单格滚轮不加速 |
| 加速键 | 按住它滚动，距离 ×2（`scrollBoostKey`，可选 Option / Command / Control / Shift / Fn，默认不使用） | 读事件**自带的 `flags`**，不查全局修饰键状态——合成事件也能带上；只放大输入，缓动曲线与时长不变 |
| 滚轮反方向 | 上下 + 左右一起反转，**只作用于鼠标滚轮** | 原地翻位移字段后**放行**原事件，不重建——保留 `phase` / `momentumPhase`，惯性不会被切断。触控板 / 妙控鼠标（`IsContinuous = 1`）不翻，方向归系统「自然滚动」 |
| 附加按键 | Forward / Back 各配一个动作，按下即执行、松开也吞掉 | 侧键 = `otherMouseDown` 的 buttonNumber **3 = Back、4 = Forward**；没配动作就返回 false，事件走老路径（按住画轨迹） |

几个刻意的取舍：

- **平滑只作用于离散滚轮**。触控板 / 妙控鼠标的事件带 `IsContinuous = 1`，系统已经平滑过，
  再来一遍是双重缓动，手感发飘。
- 🔴 **反方向也只作用于离散滚轮**。这条是踩出来的：第一版连触控板一起翻，用户开完鼠标控制
  第一句话就是"我触控板方向怎么反了"。触控板的方向在系统设置「自然滚动」里定过，那是用户
  自己的偏好；用户点「滚轮反方向」时想的多半是"我这只鼠标的滚轮反了"。判定收在
  `GestureEngine.shouldInvertScroll(invertEnabled:isContinuous:)` 一处，自检按真值表钉死。
  连续事件那条路径仍然处理加速键——倍率只改幅度、不改方向，不会把人绕晕。
- **加速键乘的是"输入"，不是"输出"**。乘在送进 `SmoothScroller.feed` 的像素位移上
  （和滚动距离一起乘），缓动轨迹的形状完全不变，只是终点远一倍——乘在派发帧上会让收尾判定
  和 `carry` 一起失真。连续滚动（触控板 / 妙控鼠标）那条路径也要生效，那里是原地缩放字段后放行。
- 🔴 **缩放同样只能动 `PointDelta` + `FixedPtDelta`**。写 `Delta` 会联动重算另两套且带取整，
  反复缩放会累积漂移；纯行滚动（像素为 0）的事件才退回缩放 `Delta`。
- **侧键没有"模式"三选一**。一颗键的行为由它自己有没有配动作决定：配了就是"按下即执行"，
  没配就是老行为（按住画轨迹）。三选一的模式会让人配出"选了动作但两个键都没设东西"的空状态，
  界面上还得再解释一遍谁覆盖谁。
- **派发出去的滚轮事件必须打 `replayMark`**。事件 tap 挂在会话最上游，自己 post 的事件会
  再进一次自己的回调——不打标记就是吞 → 派发 → 再吞的死循环。
- **余量按取整后的整数判断要不要发**。余量小于 1px 时 `round` 是 0，直接发就是一条"0 像素"
  的滚轮事件，实测一档滚轮能多发两三条空事件。
- 关开关、停引擎时 `SmoothScroller.reset()` 要清掉待滚余量，否则开关关了屏幕还会自己再滚一小段。
- 🔴 **亚像素只能走 `FixedPtDelta`**。`PointDelta` 实测**存不了小数**（写 3.4 读回来 3.0，
  写 0.4 直接变 0），指望它做亚像素就是白写。现在的做法：整数部分给 `PointDelta`
  （绝大多数应用读这个），小数部分写 `FixedPtDelta`（NSEvent 的 `scrollingDeltaY` 走这条），
  一整像素的零头由 `carry` 攒到下一帧——不攒的话一档滚轮会漏掉约 1/4 的位移。
- 🔴 **每拍都要发，不能"这帧太小就攒着"**。攒着会让相邻两条事件的间隔变成 2~3 个刷新周期
  （实测 16.7ms 变 22ms、最长 66ms），眼睛看到的就是"顿一下"。亚像素事件没人嫌多，
  一档滚轮发 19 条很正常。
- **驱动必须是显示链接**。定时器的相位和屏幕刷新对不齐，会在"这一帧走两步、下一帧不动"
  之间来回切；`CVDisplayLink` 实测 60Hz 下 16.66ms、零断档。链接建不起来（虚拟机 / 无活动
  显示器）才退回 120Hz 定时器。第一帧的 dt 取显示链接的真实帧长，写死 1/120 的话 60Hz 屏上
  会先轻轻一动、再猛地一窜。
- **缓动系数要按 dt 算**。Mos 把 `duration` 直接当"每帧的固定插值系数"，60Hz 调好的手感搬到
  120Hz 的 ProMotion 上会快一倍。我们是 `1 - exp(-dt/τ)`，帧率无关。

### 几个不能改坏的约束

- **没认出任何手势时必须原样放行事件**。吞掉右键会让所有应用的右键菜单失效。
- **短距离拖拽要当点击重放**（down 已被我们吞了，必须自己补发 down/up）。
- 🔴 **重放的事件必须打 `eventSourceUserData` 标记**。短点击会被 `replayClick` 补发 down/up，而重放事件会**再次流经自己的 event tap**（挂在整个会话最上游）——不打标记就是死循环：吞 → 重放 → 再吞 → 再重放，点一下右键红点狂闪、鼠标卡死，直到 tap 回调超时被系统禁用才停。`handle()` 开头见到 `0x424D`（"BM"）标记必须原样放行。重放时还要还原原始修饰键 flags。
- **轨迹浮层禁止整屏重绘**。`TrailView` 是全屏大小的视图，`needsDisplay = true` 会让系统重新光栅化整块 backing store，拖快一点就是每秒上百次全屏重绘，鼠标立刻卡成幻灯片。增量点用 `setNeedsDisplay(线段包围盒外扩 lineWidth×2)`。
- **修饰键在起手那一刻判一次**。按下鼠标时事件自带的 flags 就是答案，不要自己维护按键状态机；
  中途松开 ⌘ 不改判定，否则画到一半会突然换成另一条手势。
- **修饰键用全等匹配**。只建了「⌘ + 右键」时，裸右键必须照常弹系统菜单。
- **必须按同一颗键的松开收尾**：中键手势期间点一下右键，不该提前结束。
- 引擎读取的是 `GestureStore` 的实时数据，改配置立即生效，不需要重启监听。
- **应用组的成员不能只在建组时选一次**。改 `ScopeEntry.bundleIDs` 要走 `GestureStore.updateGroupScope`，并且只认 `.group`：单个应用作用域改 bundle id 等于换了个应用。组里已卸载的成员要单独列出来给「移出」，否则它既看不见也去不掉。
- **新增设置字段必须走 `decodeIfPresent` 回落**。合成解码器遇到缺键会抛 keyNotFound，外层 `try?` 再把整份配置丢掉——等于每加一个开关就清空一次老用户的设置。
- **激活策略要在建窗口之前定**：先建窗口再 `setActivationPolicy` 会留下「没有 Dock 图标、窗口还抢不到焦点」的状态。策略切换还会让应用被动失活，抢焦点要放到下一拍 runloop。
- **菜单栏浮窗不能再用 `NSPopover`**：它必定画一个指向状态项的三角箭头，还会在菜单栏底下额外留白，实测浮窗顶边离菜单栏 27pt，而它没有关掉箭头的公开开关。现在是自己定位的无边框面板，顶边直接取状态项窗口的 `minY`。
- **量完高度必须把内容视图摁回窗口大小**：测量时把 `NSHostingView` 撑到 4000 高，量完不还原的话，内容视图比窗口高，而窗口显示的是它的**底部**（原点在左下）、SwiftUI 却从顶部排——屏幕上就是一片空白，很容易误判成"面板没显示"。
- **全局点击监听要自己比坐标**：`addGlobalMonitorForEvents` 分不清点的是谁，点在浮窗内部的开关上也会触发，必须用 `panel.frame.contains(NSEvent.mouseLocation)` 挡掉，否则点一下就收起。
- **鼠标手势与触摸板手势是两套触发条件**（`Gesture.kind`）。鼠标候选只认 `kind == .mouse`，触摸板候选只认 `.trackpad`，两边都不能漏这个过滤——否则一条「3 指轻点」会被鼠标轨迹候选带上，或者一个右键手势被当成触摸板候选。
- **捏合只看方向，不看比例**。每人每块触控板张合的幅度差得远，用 `spreadRatio` 的绝对值匹配会时灵时不灵；只判 `< 1`（合拢）/ `> 1`（张开）。
- **触摸板手势里应用级要排在全局前面**。同一个「3 指轻点」在某应用里另有定义时，应用那条得先命中，不然全局那条永远赢。
- **「还原窗口」不能只把 `AXMinimized` 置 false**。窗口是回来了，但它回到的是原来的位置——那里很可能被别的应用整片盖着，应用本身也还在后台，用户看到的就是"还原了但没出现"。必须同时：取消最小化 → `AXFrontmost` 置真 → `AXRaise` → `AXMain` 置真 → `NSRunningApplication.activate()`。
- **最小化时要把窗口记下来**（`lastMinimized`，120 秒有效）。最小化之后前台通常换成了别的应用，下一次手势解析出来的 context 已经指不到原窗口，只靠 context 还原是空操作。
- 🔴 **`--install` 那一步不许再签名**。脚本里曾经是「`cp -R` 复制到 /Applications，再 `codesign --force --sign -`」——那句 ad-hoc 重签会把 `--identity` 指定的固定证书覆盖掉，cdhash 一变，「辅助功能」授权立刻失效：装完看着一切正常，手势一条都不触发。改成 `ditto` 复制 + `codesign --verify --strict` 校验，不碰签名。
- 🔴 **绝不 exec `.app/Contents/MacOS/` 里的二进制**。绕过 LaunchServices 直接跑，这个 bundle id 的菜单栏登记会**永久失效**：`statusItem.button.window.frame` 报着正常值、`isVisible` 也是 true，屏幕上就是不出现，`lsregister`／删偏好／重启 ControlCenter 全无效，唯一修法是换 bundle id（本项目已经换过一次：`com.pcxx.boxmouse` → `com.pcxx.boxmousemac`）。诊断只跑 `.build` 下的裸产物。
- **窗口下限得跟着标签页走，而且切回来还要主动撑一次**。`contentMinSize` 只约束"下一次"拖拽：在关于页把窗口缩到 520 宽，切回手势页时它不会自己长回去，顶部四个标签直接被窗口右沿切掉。`observeTab` 里除了换下限，还要调 `grow(_:toAtLeast:)` 把窗口夹到新下限（顶边不动，只往右下扩）。
- 🔴 **MultitouchSupport 的设备要拿对**。`MTDeviceCreateList()` 在头文件里被标注成 "test"，返回的数组持有设备、指针是未 retain 的；`MTDeviceCreateDefault()` 才是「能用的那个内置触控板」。两个都试，优先 default。
- 🔴 **退出时绝对不能调 `MTDeviceStop`**。它会对设备释放一次，而设备的所有权在别处（数组或框架）→ use-after-free，退出必崩。实测崩过四次，栈都一样：`MTDeviceStop → CFRelease / mt_DeviceUnregisterForHotplugNotifications → CFRunLoopSourceInvalidate`。进程退出时系统自己会回收。
- 🔴 **触点结构体的步长是 96 字节（24 个 Float），不是 72**。头文件里 `MTTouch` 的字段排布是：frame @0、timestamp @8、identifier @16、state @20、fingerID @24、handID @28、normalized @32、…、density @92。偏移对了、步长错了，第一根手指照样准、第二根开始读到的就是别的字段（角度、面积…），多指手势永远识别不出来。代码做成了运行时自适应（候选 24/22/18，取「所有触点坐标都合理」的那一套）。
- **触摸板日志的 `start ok` 那行必须带权限状态**。"框架可用、设备列得出来、引擎也说启动成功、但一个触点帧都没有"这个组合只可能是输入监控没给；把两项授权直接写进日志第一行，一眼就能判死，不用再拿探针去猜。
- 🔴 **触摸板的修饰键不能只靠 `CGEventSource.flagsState`**。鼠标手势的修饰键从「那一次鼠标事件的 flags」里读，一定准；触摸板没有事件可读，只能查键盘状态，而 Fn（地球仪键）在状态查询里**不一定可见**。候选又是**全等**匹配：配了 `{fn}`、实测 `{}` → 一条都命中不了 → 用户看到的就是「触摸板操作无效」。所以 `ModifierWatch` 做了三层兜底：`flagsState` + `keyState(key: 63)` + 全局/本地 `flagsChanged` 事件流。
- **触摸板修饰键是「起手判一次」**：手指落下那一刻读到什么，这一轮就用什么，中途松开/按下都不改（1.0.27 起放宽成"起手 200ms 窗口内判一次"，见下）。`ModifierWatch` 装在 `bootstrap` 之前，漏了会让首帧读不到 Fn。
- **重启触摸板引擎要重建设备，而不是重复注册**。`MTDeviceStop` 不能调（见上一条），所以 `stop()` 只是把 `bridge` 丢掉、下次 `start()` 重新 `MTDeviceCreateDefault()` 拿一套全新设备。旧设备的帧还在送，靠回调里的 `device` 参数 + `bridge.owns(_:)` 认出来丢掉，否则新旧两份帧一起进识别器，时间戳对不上，识别结果就是乱的。
- 🔴 **起手 150ms 内允许手指数变化，要重开一轮，不能整轮作废**。手指是**分先后落板**的：第一帧常常只报 1 根，第二帧（8~32ms 后）才报 2 根。1.0.26 及以前这里只要 `incoming != fingers` 就置 `fingerCountChanged`，而 `finish()` 又 `guard !fingerCountChanged` —— **两指滑动差一帧就永远走不到方向判定**，用户看到的就是「滑动全都无效」；单指画轨迹被拇指蹭板边多报一个触点同样整轮废掉，就是「划线基本识别不了」。现在宽限期内按稳定后的指头数 `restartRound`（重置起点/时间/轨迹）。宽限**只**罩起手，超时后再补手指仍作废（那是真换了意图）。重开必须封顶（`maxRestarts = 2`）：2↔3 来回抖时每帧都"在宽限内"，`startTime` 被无限刷新，这一轮既判不死也走不到判定，最后超时收尾还会按轻点处理，凭空多出一个「两指轻点」。
- **修饰键宽限 200ms**：人做不到把修饰键按在手指落下之前那一帧上。"起手判一次"要放宽成「起手窗口内判一次」——读不到就再等两帧，一旦读到就不再改。超时按住仍然不采纳（那一轮早就在按别的意图判了）。
- 🔴 **一轮手势的结论必须写进 `trace()`，不能只走 `appendDiag`**。`appendDiag` 开头就是 `guard isDiagEnabled`，而诊断面板没打开时 `isDiagEnabled` 是 false —— 上次排查触摸板，`trackpad.log` 里只剩一行「诊断开始」，用户到底划了什么、为什么没生效，文件里一个字都没有，只能靠猜。现在每一轮（无论命中还是作废）都由 `logRoundOutcome` 同时写面板和 `trackpad-trace.log`（一直写、60 行环），作废原因带具体数字（`作废：手指数 2→3（180ms，超出起手宽限）`）。`takeOutcome()` 会过滤掉没有多指参与的轮次，否则单指点一下也开一轮，日志会被淹没。
- 🔴 **摆窗口必须「先位置、等它真的画到位、再尺寸」，而且判"到位"只能读合成器位置**。这是「窗口操作要执行两次才准」的根因。Chromium / Electron（Edge、WorkBuddy）把 AX 的位置变更做成约 **200ms 的平滑过渡**，并且 **AX 的 `AXPosition` 在写入后立刻就读到目标值**（乐观更新）—— 无论用属性值判断"到没到"，都会误判成已到位，于是在过渡途中写 `size`，窗口被定格甚至弹回起点。真实渲染位置的轨迹（`CGWindowList` 每 40ms 采样）：`236 → 468 → 541 → 568 → 570`，而 AX 读回全程报 570。修法：写完 position 后用 `CGWindowListCopyWindowInfo([.optionIncludingWindow], number)` 轮询**这一个窗口**的真实位置（20ms 一拍，3pt 容差），到位后再写 size，100ms 后补一次位置（改高度会按 NS 左下角锚点带偏）。原生 AppKit 应用是瞬时的，第一拍就过，不额外等待。
  - 实测对照（目标 x=570 w=1140，起点左半屏 x=0 w=855）：`position → size` 落到 x=0（位置全丢）；`position → 120ms → size` 落到 x=499（停在过渡中间）；`position → 280ms → size` 正确。旧实现尾部那次多余的 `position` 也会把尺寸打回去 —— 它在 Electron 上等于"把刚设好的尺寸还原成旧值"。
  - `AXFrame` 看着能一次原子写完位置 + 尺寸，但 Chromium 返回 `-25200`（不支持写），只读。
  - 诊断入口：`.build/release/BoxMouse --windowseq`（拆序列对比）、`--windowop <op> [--resize w,h] [--repeat n]`（带采样轨迹）。这两个工具是这次定位的全部依据，别删。
- 🔴 **滚轮的三套位移字段是联动的一份数据，只能翻 `PointDelta` / `FixedPtDelta`，绝不能翻 `Delta`**。`CGEvent` 上 `DeltaAxis`（行）、`PointDeltaAxis`（像素）、`FixedPtDeltaAxis`（16.16 定点）看着是三套独立字段，实测：
  - **写 `Delta` 会联动重算另外两套**，而且换算带取整、不可逆：`30 → 翻一次 -24 → 再翻一次 24`，来回拨两次位移就缩水；触控板事件的 `Delta` 恒为 0，写它会把整条事件的像素位移**清零**——反方向一开就等于滚不动。
  - 写 `PointDelta` / `FixedPtDelta` 只改自己，精确、可逆、互不牵连。所以主路径只翻这两套；只有"纯行滚动"的老式事件（像素位移为 0、行位移非 0）才退回翻 `Delta`。
  - 第一版就是"逐个翻六个字段"，结果位移翻倍（12 → 24），被自检的"翻两次要回到原值"逮住。断言里连联动关系一起钉死了，别改成"更对称"的写法。
  - 🔴 **抓非 onscreen 窗口的 `screencapture -l` 会拿到未渲染的图层**：开关全显示成"关"，看着像状态没同步。验证界面状态要用 `screencapture -R <窗口区域>`（窗口真在前台），几何读 AX 的 `AXPosition`/`AXSize`——调度中心（Mission Control）开着时 `CGWindowList` 报的是**缩放后**的窗口框，会误判成"窗口被改了"。


## 版本规则

`VERSION` 是唯一来源。`build-app.sh` 对 `Sources/` `Resources/` `tools/` `Package.swift` `build-app.sh` 取 sha256 指纹，与 `VERSION.fingerprint` 比对：

- 指纹变了 → 补丁号 +1（1.0.0 → 1.0.1）
- 只改文档、反复构建 → 版本号不动
- 首次打包没有指纹文件 → 沿用 VERSION 里的初版号

## 发版（dmg + GitHub Releases）

对外发版才做这一步，日常装机只要 `dist/BoxMouse.app`。

```bash
./build-app.sh --no-sandbox --identity "FastFind Local Signing"   # 先出包（会跑自检门禁）
./tools/make-dmg.sh                                               # → dist/BoxMouse-<版本>.dmg
gh release create v<版本> dist/BoxMouse-<版本>.dmg \
    --title "BoxMouse <版本>" --notes-file notes.md --target main
```

`make-dmg.sh` 做三件事：校验签名与包内版本号一致（防止把上一版的壳当新版发出去）、
用 `ditto` 把 app 和 `Applications` 软链组装成拖拽安装样式、打完 `hdiutil verify` 验一遍。

- 🔴 **`dist/` 在 `.gitignore` 里**，dmg 不进版本库，只走 Releases 附件。
- 本机证书是自签名（不是 Apple Developer ID），别人下载后首次打开会被 Gatekeeper 拦，
  需要右键 → 打开，或「系统设置 → 隐私与安全性 → 仍要打开」。脚本会把这个提示打出来。
- 🔴 **脚本里变量后面紧跟中文/全角括号时一律写 `${VAR}`**。`$OUT_PATH（` 会被 bash
  并进变量名，`set -u` 下直接 `unbound variable` 崩掉。

## 图标

应用图标用设计稿位图加工，不靠代码画：

```bash
# ① 源图自带底板（如蓝色渐变底 + 白图案）
python3 tools/prepare-icon.py assets/icon-raw.jpg assets/icon-source.png

# ② 源图是透明底的纯图案（会套一块白色圆角底板）
python3 tools/prepare-icon.py assets/icon-raw-transparent.png assets/icon-source.png --tile

# ③ 源图已经自带圆角底板（当前这一版：白底 + 橙色节点图）
python3 tools/prepare-icon.py assets/icon-raw-tiled.png assets/icon-source.png --keep-tile
```

`prepare-icon.py` 有三种模式：

- **默认**：找出图标体的方框 → 四角泛洪抠掉白底（阈值 250，边缘做轻微羽化，深色背景下不留白角）→ 重排到 macOS 图标栅格。
- **`--tile`**：源图是透明底的纯图案时用它。按 alpha 裁到图案边界、补成正方形、缩到图标体的 90%（四边各留 5%，再大就不是 macOS 图标的比例了），再摆到一块**白色圆角底板**上（圆角半径取图标体边长的 22.37%，8 倍超采样再缩回，边缘无锯齿）。透明底的图案直接当图标会"飘"在 Dock 里，四个圆环中间透出壁纸，缩小后糊成一团。
- **`--keep-tile`**：源图自己就带圆角底板时用它。只按栅格重排（裁掉画布留白 → 底板缩到 824 → 居中到 1024），圆角半径与图案比例**原样沿用设计稿**。这种情况千万别再套一层底板，否则圆角会被强行换成 Apple 的 22.37%，跟设计稿对不上。

三种模式都输出 1024 画布 / 824 图标体的母版，`build-app.sh` 再把它出成 iconset + icns。

早期版本用 `tools/render-icon.swift` 纯代码画过一个"指针 + 轨迹"图标，现已不参与打包，文件留着备查。1.0.22 之前的蓝色渐变底板母版备份在 `assets/drafts/icon-source-blue-1.0.22.png`。

**菜单栏图标是另一套**（`UI/MenuBarIcon.swift`）：18×18 按 2 倍像素绘制、`isTemplate = true`，由系统按菜单栏明暗自动上色。字形是**四个空心圆环 + 三段圆头连线**（菱形节点图），几何按参考图实测换算：环外径 20、线宽 4、节点中心间距 44.5，等比缩到 18pt 后外径统一 4.7、线宽取 1.05。

线宽有取舍：严格等比只有 0.92，环内孔更通透但比系统图标细一档；1.35 更"实"但内孔被挤小。四个变体都在 `MenuBarGlyphVariant` 里，`defaultVariant` 定的是折中档。

```bash
./.build/debug/BoxMouse --dump-menubar-icon /tmp/glyph.png          # 当前字形
./.build/debug/BoxMouse --dump-menubar-variants /tmp/v               # 四个变体 + 模拟菜单栏
```
